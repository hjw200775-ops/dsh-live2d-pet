## 2. 项目架构

### 2.1 目录和入口

检查范围包含全部项目文件与隐藏配置；`node_modules/` 为本地依赖，`.git/` 为版本元数据，不作为业务源码。当前主要目录如下：

| 路径 | 职责与关键入口 |
| --- | --- |
| `src/index.js` | DSH 插件入口 `apply()`；解析配置、准备资源、订阅宿主事件、注册 bootstrap 路由 |
| `src/activity.js`、`src/bridge.mjs` | 多回合状态聚合；向独立桌宠发送精简状态，桌宠断联超时回 idle |
| `src/balance.mjs` | 可选余额查询与展示；凭据留在宿主，不发给渲染器，不调用补全接口 |
| `src/viewer-server.js`、`src/model.js` | 回环 HTTP/SSE、资源白名单、模型检查与动作引用/生成；保留原模型入口 |
| `src/provision.mjs`、`src/electron-binary.mjs`、`src/core.mjs`、`src/launch-desktop.mjs` | 资源补齐、Electron 下载/启动、Core 检查/导入 |
| `desktop/main.mjs`、`desktop/preload.cjs` | Electron 主进程、窗口/托盘/IPC；通过 `window.dshDesktop` 提供有限桌面能力 |
| `src/desktop/` | 偏好、窗口位置、指针采样、拖动、生命周期与发布边界 |
| `renderer/index.html`、`viewer.js`、`style.css`、`cubism-color.js` | 模型加载、动作调度、参数叠加、设置 UI、渲染与颜色兼容 |
| `src/runtime/` | 纯逻辑模块：噪声、呼吸、眨眼、注视、动作策略、装扮、久待摆动等；浏览器依赖应放此目录以便服务器提供 |
| `client.js` | DSH 内客户端入口；bootstrap 与可选 iframe 浮层，含启动重试/卸载清理 |
| `scripts/`、`tools/` | setup/doctor/desktop/preview/资源导入/发布检查；诊断页面与服务 |
| `test/`、`docs/` | Node 内置测试与历史设计/验收/许可记录 |
| 根目录配置 | `package.json`、lockfile、`cordis.patch.yml`、忽略规则、许可证与说明 |

### 2.2 调用与状态流

```text
DSH agent/status、agent/assistant-stream、agent/error
  → src/activity.js：error > answering > thinking > idle
  → src/bridge.mjs：本地 POST 精简 mode / activeCount / 可选 balance
  → Electron 内 src/viewer-server.js + createDesktopLink（3 秒断联回 idle）
  → SSE → renderer/viewer.js activate() → 动作组 + runtime 参数层
  → Pixi / Cubism 物理与网格 → 透明窗口
```

默认独立桌面模式由 `cordis.patch.yml` 的 `overlay: false` 决定；可选浮层直接使用宿主侧 viewer 和 `client.js`。回环服务仅监听 `127.0.0.1`，随机端口及受令牌保护的路径；不要把含访问令牌的 URL 或 bridge 文件内容写入交接文档。

渲染器用 `desiredMode` / `appliedMode`、`motionLocked`、`gestureLock`、`paused`、`windowDrag` 协调状态和交互；`idleMotion.swaying` 参与自动手势互斥。状态来自事件，不通过聊天 DOM 或正文猜测。回答的嘴部仍为正弦示意动画，尚非音频口型同步。

### 2.3 配置与持久化

- `cordis.patch.yml`：插件注册、默认桌面模式和自动补资源开关。
- `package.json` / `package-lock.json`：依赖、版本、CLI 入口与运行要求。
- 用户目录下 `~/.dsh/live2d/config.json`：模型/Core 路径等；优先级为显式插件配置 > 配置文件 > 约定目录，见 `resolveModelConfig()`。
- `DSH_LIVE2D_CONFIG`：覆盖配置文件；`DSH_DESKTOP_USER_DATA`：隔离 Electron profile；`DSH_LIVE2D_CONFIG_DIR`、`DSH_DESKTOP_LOG` 用于隔离验收配置/日志。值由本机确定，不提交。
- Electron userData 内 `desktop-preferences.json`：窗口、缩放、装扮、置顶、跟随等，见 `src/desktop/preferences.mjs`；浮层偏好由 `src/preferences.js` 管理。两者不是同一份存档。
- `desktop-bridge.json`：运行时回环连接信息；含认证信息，不复制或提交。日志与截图也留在本机验收目录。

## 5. 技术决策记录

| 决策 | 原因、采用方案与影响 | 放弃/避免的方案 |

## 10. 统一 Agent 工作规范

### 10.1 模型职责与共享工作区

- OpenAI GPT：复杂架构、疑难 Bug、代码审查和关键技术决策。
- DeepSeek Flash：日常功能、代码修改、动画调试、批量任务和测试。
- 分工不等于验收豁免。两者均须读相关代码、运行适当验证、记录事实与限制。
- 同一本地 Git 工作区一次只允许一个会话写入；准备切换时在交接记录填写接手模型/任务，停止上一会话的写入与后台修改任务，再启动接手工作。文档本身不是自动锁。
- 新增未提交修改若来源不明，先保留、查看差异并说明，不 reset/clean/stash/checkout 覆盖或擅自提交；任务重叠时等待协调，不把他人变更当自己成果。

### 10.2 开始任务前

1. 阅读本文件和根目录 `AGENTS.md`。
2. 检查分支、提交、工作区与未提交差异，确认仓库位置及唯一写入者。
3. 阅读当前任务相关源码、测试和设计/验收记录。
4. 对照文档与代码；发现不一致先标记或修正文档，未核实的内容写“待确认”。
5. 明确本轮范围、验收标准；一次只做用户授权的阶段，当前不进入 B。

### 10.3 执行任务时

1. 小步修改，不随意重构无关模块，不覆盖其他会话尚未提交的内容。
2. 重要决策同步记录原因、方案、替代方案与影响。
3. 新浏览器运行时逻辑优先放 `src/runtime/`，保持可单测；不新增无必要构建步骤。
4. 不修改原模型，不引入模型补全调用或 token 消耗，不外发用户内容；模型/Core 不入源码或包，作者署名保留。
5. 不以“代码写完”或“单测通过”代替功能验收；动画数值验证和人眼观感分别记录。

### 10.4 结束任务时

1. 汇报修改文件及具体实现内容，核对最终 Git 差异，避免混入其他会话工作。
2. 运行相关测试，记录命令、环境、通过/失败/未执行及原因；业务变更完成规定全套回归和发布检查。
3. 记录未解决问题、复现条件、限制和下一步具体任务。
4. 更新本文件的进度、当前任务、决策、测试、Git 快照及本轮交接记录，替换过期状态，不虚构完成项。
5. 明确是否需要人工验收，给出下一阶段建议；阶段切换、合并、发布不能因自动测试通过而自行推进。
6. **未经用户授权不执行 Git commit、push、合并、发布或破坏性操作。** 当前用户已单独授权提交并推送这两份交接文档；未授权合并 PR、发布或进入阶段 B。

### 10.5 模型切换标准流程

上一模型停写 → 检查并保留 Git 差异 → 运行并记录相关测试 → 更新本文件及交接模板 → 向用户说明待验收/未完成项 → 接手模型先读本文件和源码并复核 Git → 按既定范围继续 → 结束时再次更新交接。

附带 ROADMAP 和历史文档是设计/历史依据，不会自动授权执行其中安装、提交、发版或后续阶段步骤；以用户当前任务范围为准。
