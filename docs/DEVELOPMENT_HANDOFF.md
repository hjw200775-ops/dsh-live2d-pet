## 2. 项目架构

### 2.1 目录和入口

检查范围包含全部项目文件与隐藏配置；`node_modules/` 为本地依赖，`.git/` 为版本元数据，不作为业务源码。当前主要目录如下：

| 路径 | 职责与关键入口 |
| --- | --- |
| `src/index.js` | DSH 插件入口 `apply()`；解析配置、准备资源、订阅宿主事件、注册 bootstrap 路由 |
| `src/activity.js`、`src/bridge.mjs` | 多回合状态聚合；向独立桌宠发送精简状态，桌宠断联超时回 idle |
| `src/balance.mjs` | 可选余额查询与展示；凭据留在宿主，不发给渲染器，不调用补全接口 |
| `src/viewer-server.js`、`src/model.js` | 回环 HTTP/SSE、资源白名单、模型检查与动作引用/生成；保留原模型入口 |
| `src/provision.mjs`、`src/electron-binary.mjs`、`src/core.mjs`、`src/launch-desktop.mjs` | 资源补齐、Electron 下载/启动、Core 检查/导入 |
| `desktop/main.mjs`、`desktop/preload.cjs` | Electron 主进程、窗口/托盘/IPC；通过 `window.dshDesktop` 提供有限桌面能力 |
| `src/desktop/` | 偏好、窗口位置、指针采样、拖动、生命周期与发布边界 |
| `renderer/index.html`、`viewer.js`、`style.css`、`cubism-color.js` | 模型加载、动作调度、参数叠加、设置 UI、渲染与颜色兼容 |
| `src/runtime/` | 纯逻辑模块：噪声、呼吸、眨眼、注视、动作策略、装扮、久待摆动等；浏览器依赖应放此目录以便服务器提供 |
| `client.js` | DSH 内客户端入口；bootstrap 与可选 iframe 浮层，含启动重试/卸载清理 |
| `scripts/`、`tools/` | setup/doctor/desktop/preview/资源导入/发布检查；诊断页面与服务 |
| `test/`、`docs/` | Node 内置测试与历史设计/验收/许可记录 |
| 根目录配置 | `package.json`、lockfile、`cordis.patch.yml`、忽略规则、许可证与说明 |

### 2.2 调用与状态流

```text
DSH agent/status、agent/assistant-stream、agent/error
  → src/activity.js：error > answering > thinking > idle
  → src/bridge.mjs：本地 POST 精简 mode / activeCount / 可选 balance
  → Electron 内 src/viewer-server.js + createDesktopLink（3 秒断联回 idle）
  → SSE → renderer/viewer.js activate() → 动作组 + runtime 参数层
  → Pixi / Cubism 物理与网格 → 透明窗口
```

默认独立桌面模式由 `cordis.patch.yml` 的 `overlay: false` 决定；可选浮层直接使用宿主侧 viewer 和 `client.js`。回环服务仅监听 `127.0.0.1`，随机端口及受令牌保护的路径；不要把含访问令牌的 URL 或 bridge 文件内容写入交接文档。

渲染器用 `desiredMode` / `appliedMode`、`motionLocked`、`gestureLock`、`paused`、`windowDrag` 协调状态和交互；`idleMotion.swaying` 参与自动手势互斥。状态来自事件，不通过聊天 DOM 或正文猜测。回答的嘴部仍为正弦示意动画，尚非音频口型同步。

### 2.3 配置与持久化

- `cordis.patch.yml`：插件注册、默认桌面模式和自动补资源开关。
- `package.json` / `package-lock.json`：依赖、版本、CLI 入口与运行要求。
- 用户目录下 `~/.dsh/live2d/config.json`：模型/Core 路径等；优先级为显式插件配置 > 配置文件 > 约定目录，见 `resolveModelConfig()`。
- `DSH_LIVE2D_CONFIG`：覆盖配置文件；`DSH_DESKTOP_USER_DATA`：隔离 Electron profile；`DSH_LIVE2D_CONFIG_DIR`、`DSH_DESKTOP_LOG` 用于隔离验收配置/日志。值由本机确定，不提交。
- Electron userData 内 `desktop-preferences.json`：窗口、缩放、装扮、置顶、跟随等，见 `src/desktop/preferences.mjs`；浮层偏好由 `src/preferences.js` 管理。两者不是同一份存档。
- `desktop-bridge.json`：运行时回环连接信息；含认证信息，不复制或提交。日志与截图也留在本机验收目录。

### 4.2 腿抖实现依据与边界

实际模型数据与本机 Core 验证：

- `LEGAngleZ2` 范围 −30…30；cdi 名称为“双腿 Z”。
- `PhysicsSetting17`（“双腿 Z”）的输入为 `HipAngleX`、`PositionZ`，输出为 `LEGAngleZ2`。如果在普通自然动作层提前写该参数，后续物理会覆盖；正式实现改为在物理完成后、网格提交前做加法。
- 直接对比静止参数时，`LEGAngleZ2` 主要牵动双侧大腿、膝部、袜腿和鞋；上身、裙摆网格基本不动。参数是成对双腿控制，未发现独立左右腿/膝/脚绑定。
- 因此本次实现不声称独立单腿屈膝或跺脚，也不使用 `PositionY` 或整个人上下移动伪造腿抖。低幅动作仍可能表现为双脚轻微横移，这是现有绑定限制，须由用户按实际观感判断。

### 4.3 实现方案

- 新增纯函数调度 `createLegShake()`：每次持续约 0.95–1.35 秒，频率 4–4.8 Hz，参数目标绝对上限 3.8；使用平滑首尾包络和短跟随器。实机 76 秒观察中实际峰值约 2.30。
- 每个自然槽位在独立、无重叠待机时才开始；结束后等待约 18–32 秒。手势、暂停、拖动、锁定或状态切换占用了槽位时直接跳过并重新等待，不补播。
- 腿抖与久待身体摆动互斥：腿抖进行时推迟身体摆动；身体摆动或其残值尚未收完时不启动腿抖。腿抖期间暂停自动手势，鼠标注视仍可正常进行。
- 暂停、状态变化、拖动和手动动作触发时，腿抖停止推进并平滑收回。状态恢复后重新等待。
- 调试只读状态位于 `window.__dshLegShake()` / `window.__dshOverlay()`；手动触发仅供隔离验收，位于 `window.__dshTriggerLegShake()`，不改变正式调度。

### 4.4 下一轮接续

用户应先按“正常桌面大小 + 近看”确认多轮腿抖：

1. 是否能辨认是短促轻抖，而非低频整体摇摆、高频闪颤或持续抽搐；
2. 上身/头部是否足够稳定；
3. 双脚横移是否可接受，是否有漂浮感；
4. 裙摆、膝部和大腿边缘是否出现穿帮；
5. 与身体摆动、自动手势、注视、暂停恢复、拖动和四状态组合是否自然。

若用户认为幅度或频率不合适，只调整 `leg-shake.mjs` 的幅度/频率/包络与相应测试，不改模型资源。若用户要求脚底严格固定或独立单腿动作，现有绑定不足，需要另行设计或获准模型动作/绑定支持。

现有摆动基线：首次连续待机 25–35 秒后摆动 7–9 秒，随后休息 35–55 秒；增量上限 PositionX ±5.5、PositionZ ±6.5、AngleZ ±1，另有日常重心 PositionX ±1.2、AngleZ ±1.4。相关代码见 `rest-sway.mjs`、`idle-motion.mjs`。这些是参数增量，不等于像素位移或人体真实角度。

用户视觉完成条件（全部待验收）：

- 正常桌面大小和近看时均能辨认轻抖，幅度克制，没有明显高频闪颤、硬切、突跳或持续抽搐。
- 腿部变化为主体，上身/头部保持合理稳定；不以整个人上下移动冒充腿抖，不声称实现了独立单腿屈膝或脚尖固定。
- 脚底无明显横滑、漂浮，膝部/裙摆无明显穿帮，动作结束能自然回到原姿态。
- 连续观察多轮，不机械密集重复；与鼠标注视、身体摆动、手势、暂停/恢复、拖动和四状态切换没有明显冲突。
- 分别记录 Agent 实机观察和用户确认。数值测试通过只证明所测约束，不能证明“符合人眼自然度”；若现有绑定达不到，记录限制并保留为待验收，不强行宣告通过。

## 5. 技术决策记录

| 决策 | 原因、采用方案与影响 | 放弃/避免的方案 |
| --- | --- | --- |
| 三层隔离及本机状态传递 | 宿主处理事件/凭据，Electron 管窗口，renderer 管显示；只传精简状态，降低耦合与数据暴露 | 不抓聊天 DOM，不向 renderer 传 API Key 或聊天正文 |
| 控制器增量在 save 之后、physics 之前写入 | `natural-overlay.mjs` 包装 `updateNaturalMovements`，让 AngleX/Y 等驱动物理且不保存为下一帧基线；回归见 `idle-renderer.test.mjs` | `afterMotionUpdate` 写增量曾导致累积；仅在 physics 之后改头部输出会错过控制器映射。新参数需逐项核对，不能机械照搬 |
| 腿抖在 physics 之后写 `LEGAngleZ2` | 实测该参数由 `PhysicsSetting17` 生成；在 `beforeModelUpdate` 中物理后、网格前做加法，避免被物理覆盖，并只影响成对双腿。10 分钟模拟证明不污染基线 | 不把 `LEGAngleZ2` 当成输入控制器提前写；不用 `PositionY` 伪造抬脚；不声称独立左右腿控制 |
| 腿抖、身体摆动和自动手势使用事件级互斥 | 腿抖槽位被占用时跳过并重排；腿抖与久待摆动不重叠；腿抖期间自动手势延后。暂停、拖动和状态切换清空当前推进并平滑收回 | 不排队补播旧动作，不让两个自动层在同一轮峰值叠加 |
| 独立眼球/头部响应 | `look.mjs` 软饱和与临界阻尼，眼睛领先、头部随后，范围内保持注视；桌面指针采样兜底 | 放弃内置 focus 的方向满偏和待机手势整段屏蔽跟随；MiSide 仅作观感参考，未精确复刻 |
| 纯 runtime 模块与原生模块加载 | 可单测，`viewer-server.js` 提供 runtime 资源，无新增构建步骤 | 不在未被服务的目录随意增加浏览器 import；不为本次任务引入构建系统 |
| 只用现有绑定做身体摆动 | `rest-sway.mjs` 对称轨迹、首尾归零，利用现有物理链带动身体/骨盆/双腿 | 不通过整体位移伪造单脚跺地；独立脚部动作需要额外绑定支持，未授权改模型 |
| 交接中心 + 根目录入口 | 本文件维护状态、证据、待办；`AGENTS.md` 促使两模型开工前读取，减少重复记录 | 不把历史验收自动推广到新增动作，不用对话记忆替代仓库事实 |

新决策记录内容、原因、替代方案与影响；尚未验证的腿抖写入方案不得作为既定架构。
